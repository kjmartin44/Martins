# Getting the analysis tables

[Documentation index](index.md)

Generated by `python scripts/generate_data_docs.py`. The entries below
come from `generoutes/datasets.py`, which imports the search
paths from the loaders themselves, so this list cannot drift from what
the code actually looks for.

Every table here is optional and the analysis runs without all of them.
That is the design: a missing file costs you a section and the report
says which. It also makes one question hard to answer — *have I got
everything I meant to get?* — so start with the command that answers it:

```sh
python -m generoutes.datasets
```

**Run it from the checkout root.** Every loader resolves `data/...`
against the working directory, so from anywhere else this reports
almost nothing present — which looks like missing downloads and is not.
The output names the directory it searched, so you can tell the two
apart.

It lists every table, whether this checkout has it, and for anything
absent, where to get it and what the run loses. Add `--missing` for a
shopping list, and `--count` to open each present file and say how much
is in it.

`--count` reports a unit, and the unit is the point. *879 motifs* came
from the motif parser, so the file is a PFM file. *2,225,583 lines, not
parsed* means the stream opened and ran to the end — which catches a
truncated download and says nothing about whether the content is what
it claims. Every table can be counted; ten of them only by line,
because parsing a gigabyte to prove it arrived is not a good trade.

```sh
python -m generoutes.datasets --missing
python -m generoutes.datasets --key gnomad --count
```

## Where to start

You do not need all of this, and the order matters more than the
total. The first three change the answer most.

| Order | Table | Why this one first |
| --- | --- | --- |
| 1 | ChIP peaks | measured occupancy. Without it, factor ranking rests on sequence alone and most of a motif hit list is chance |
| 2 | JASPAR motifs | 879 matrices instead of a handful, so real factors are tested at all |
| 3 | a drug table | the screening library and the targets per drug, which removes the whole ChEMBL dependency |
| 4 | a regulon table | how many genes each factor controls |
| 5 | GENCODE GTF | TSS lookup and the neighbour check, with no network |
| 6 | HPA expression | whether a factor is expressed where your gene is |
| 7 | gnomAD + ClinGen | whether there is room to move the gene, and whether moving it is safe |
| 8 | the rest | BindingDB, LINCS, DepMap, PRISM, Orange Book, GWAS, GOA, HGNC |

## How files are found

Three different things happen, and the inventory labels each entry with
which:

**Found by name under `data/`.** Put the file there with one of the
accepted names and the loader picks it up. Several names are accepted
per table because the upstream download name changes between releases —
any one of them works.

**Passed with a flag.** The biggest three are explicit, so one
checkout can hold several versions and a run says in its own query block
which it read.

**Built from other files.** Three tables are built from the others, and one more is downloaded
and then projected down to the columns this package reads. The command
is given in each entry.

## A note on releases

Which release you take is not a detail. gnomAD v2.1.1 and v4.1 give
different pLI and LOEUF for the same gene — different cohort, different
transcript set, LOEUF recomputed — and ClinGen is re-dated weekly, so a
gene can move from "no evidence available" to curated between two runs.

The run records the release it read for both of those tables, in the
result and in the report, taken from the file rather than from
configuration. Where a file does not state a release the field says so
instead of guessing. For the rest, the result carries the size,
modification time and sha256 of every file passed by flag, which is the
next best thing.

## Terms, and what this repository ships

**The repository ships none of the tables below.** Each accepted
filename has its own rule in `.gitignore`, so a download you drop into
`data/` stays out of git, and the installed wheel carries no data at
all — `MANIFEST.in` does not include `data/` and the package finder
takes only `generoutes*`.

One file under `data/` *is* tracked, and it is not one of these:
`data/hpa.tsv`, a small tissue-to-organ lookup. It has `Tissue` and
`Organ` columns and is **not** an expression matrix — the table that
answers "how much of this gene is in this tissue" is the HPA consensus
download listed below.

That matters the moment you do. Each source sets its own terms on the
page its entry links to, and they are not uniform: some require
attribution, several are share-alike, and a few distinguish academic
from commercial use. They also change between releases. So before you
share a `data/` directory, a built table or a results archive with
anyone outside your group, read the terms at the source rather than
assuming they are permissive.

Two consequences worth stating plainly:

A **derived table inherits from its inputs.** `chip_regulon.tsv` is
built from ReMap and GENCODE and carries whatever those two require.
`bindingdb_distilled.tsv` is a projection of BindingDB, not a new work.

A **saved result can embed source data.** `results.json` holds drug
names, target annotations and measured values that came from these
tables. It is not a bibliography, it is an extract.

The run records what it read — the package version, a UTC timestamp,
and for every file passed by flag its size, modification time and
sha256; plus, for the two dosage tables, which release answered. That
is provenance, which is a different thing from permission, and it is
what lets you answer "which file produced this number" later.

## What a download that silently failed looks like

A captive portal, an expired link or a rate limit returns a page with
HTTP 200 and the name you asked for, and `curl` reports success. A size
check does not catch it: an HTML apology can be any length, and the
sizes above are approximate anyway — JASPAR is 284 KB, which looks like
a truncated download if you were expecting megabytes. Check content
instead:

```sh
head -2 data/jaspar2024.txt          # should start with >MA
python -m generoutes.datasets --count
```

`--count` is the real check, because where it parses it does so with
the same loader the analysis uses. A table that is present and
unreadable is reported as an error rather than left looking fine — that
case is worse news than a table that is simply absent, and it should
not read the same.

### BindingDB measured affinities

Measured potency, and known ligands for the docking gate.

| | |
| --- | --- |
| Supplied | found by name under data/ |
| Looks for | `data/bindingdb_distilled.tsv`, `data/BindingDB_All.tsv`, `data/bindingdb_all.tsv`, `data/BindingDB_All.tsv.gz`, `data/bindingdb.tsv` |
| Size | 9 GB unpacked, 268 MB distilled |
| Source | <https://www.bindingdb.org/bind/chemsearch/marvin/Download.jsp> |
| Inventory key | `potency` |

Prepare it once after downloading:

```sh
python -m generoutes.localpotency --distil data/BindingDB_All.tsv
```

**Without it:** the potency axis in drug scoring has nothing to read and the established-ligand ranking loses its order.

The full release is 640 columns and seven are read, so distil it once: 268 MB afterwards, and read in six seconds rather than three minutes. Check it landed with `python -m generoutes.localpotency --uniprot P51681`.

Leave `--min-pchembl` alone unless you know why. A row-level threshold drops weak Ki measurements and lets a stronger IC50 win the assay preference, which changes the answers rather than only the file size.

A censored value ('>10000 nM') is dropped rather than converted, because recording it as a number would turn a failed experiment into a weak measurement.

## Checking the whole set

The inventory says what is on disk. A real run says whether the analysis
could use it, which is not the same question — a file can parse and
still answer nothing for your gene:

```sh
python -m generoutes --gene CCR5 --direction down --offline \
    --pfm-file data/jaspar2024.txt \
    --chip-bed data/remap2022.bed.gz \
    --regulon-file data/chip_regulon.tsv \
    --expression-file data/rna_tissue_consensus.tsv \
    --gtf data/gencode.basic.gtf.gz \
    --out results/offline_check
```

`--offline` forbids the network entirely, so anything that answers came
from a file. Then read the evidence table at the top of the report. It
names every source as `ok`, `ok, nothing found`, `FAILED` or `not
requested`.

Those four are the point. **A source that failed is recorded as failed,
never as zero**, and `ok, nothing found` means the source was reached,
it answered, and the answer was nothing — a measurement, and not a find.
Reading that table before the ranking underneath it is the difference
between a result and a list.
